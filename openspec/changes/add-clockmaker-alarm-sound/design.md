## Context

The Clockmaker Notebook timer fires silently today. `ScribeModSystem.MyTimerChanged` fires client-side whenever the timer state changes (including the Running→Fired transition); this is already the hook point for refreshing the HUD and the Clockmaker dialog. `ILoadedSound` (vanilla VintagestoryAPI) supports per-frame `SetVolume(float)` alongside built-in `FadeIn`/`FadeOut`, giving us full control over the volume envelope. The sound file is a ~26.4s mechanical alarm clock OGG (Freesound #78562, CC BY 4.0) whose natural length comfortably fills the 30s `TimerStore.FiredAutoClearSeconds` window without looping.

`SoundParams.Volume` is clamped to 0..1 by its setter. `SetVolume(float val)` passes `val` directly to OpenAL but also stores it via the clamped setter; treat 1.0 as the hard ceiling.

## Goals / Non-Goals

**Goals:**
- Play the alarm OGG exactly once when the timer fires; stop on dismiss or natural end.
- Implement a three-phase volume envelope: easeInCubic ramp-up (1s), sine-wave breathing (±10%, 3s period), easeInOutSine fade-out on dismiss (500ms).
- Keep peak volume ≤ 1.0; calibrate nominal volume against bear growl at 10 blocks.
- Both dismiss paths (HUD click, Stop Timer button) trigger the fade-out.
- No Core changes; no server-side logic; no new mod dependencies.

**Non-Goals:**
- Per-player mute preference (volume is a dev-tuned const for now).
- Volume UI slider.
- Looping or restarting behavior.
- Any server-side sound notification.

## Decisions

### D1 — Custom tick-driven volume envelope, not VS built-in fades

`ILoadedSound.FadeIn` and `FadeOut` are linear (multiplicative-step). The spec requires easeInCubic for ramp-up and easeInOutSine for dismiss fade-out; these curves produce a meaningfully different feel (stays quiet longer then rises quickly; symmetric ease for the exit). Implementing a custom `RegisterGameTickListener` loop with `SetVolume(float)` per frame gives exact curve control with minimal code.

The ramp-up and breathing phases share the same tick; the fade-out replaces the breathing update in a distinct phase state. This is simpler than two separate listeners.

### D2 — `EnumSoundType.Ambient` to skip positional attenuation

The alarm is bound to the player, not a world position. Ambient type plays at the configured volume regardless of player movement, which is correct for a timer notification. Entity or block sound types would require a meaningful world position and would attenuate with distance from it.

### D3 — Breathing as relative sine multiplier on nominalVolume

`volume = nominalVolume * (1.0 + 0.1 * Math.Sin(2π * t / breathPeriod))`. The ±10% swing is relative, so the absolute value stays bounded by `nominalVolume * 1.1`. Constraint: `nominalVolume ≤ 0.909f` so the +10% peak never exceeds 1.0. The named constant `ScribeAlarmSound.NominalVolume` starts at `0.65f` and is wired into the `.geartune` tuning window for in-session calibration.

### D4 — Dismiss paths call a single `ScribeModSystem.DismissAlarm()` method

Both the HUD fired-row click and the Stop Timer button already call `ScribeModSystem` for the timer-clear network packet. Adding a `DismissAlarm()` call at the same sites keeps the sound lifecycle inside `ScribeModSystem` without leaking `ScribeAlarmSound` into the HUD or dialog.

### D5 — Natural clip end → silent idle, no auto-restart

At ~26.4s the clip ends. If `TimerAutoDisappear = false` and the player hasn't dismissed, the HUD stays animated but the sound is simply silent from 26.4s until the player clicks. This matches real alarm clocks that spring down and tick quietly. No restart logic needed; `HasStopped` can be polled in the tick to detect natural end and cancel the listener.

### D6 — Asset prep is a manual task, not generated by build

The OGG must be normalized to peak −1 dBFS and exported at 44.1 kHz mono ~192 kbps OGG Vorbis. This is a one-time step performed by the author (Audacity or similar). The file is checked in to source control. No build-time audio processing.

## Risks / Trade-offs

- **SetVolume clamp at 1.0 limits breathing headroom** → Fixed by keeping `nominalVolume ≤ 0.909f`. The breathing range is asymmetric if nominalVolume is close to 0.909 (more room below than above), which is inaudible in practice.
- **`RegisterGameTickListener` fires at render framerate; dt is the delta** → Use accumulated elapsed time, not frame count. The tick is removed via `UnregisterGameTickListener` when the alarm reaches Done state.
- **Player relogs mid-alarm** → `MyTimerChanged` fires on relog with the current Fired state; `StartClientSide` re-creates `_activeAlarm` just like a new fire. `FiredElapsedSeconds` is already persisted server-side, so if elapsed > 26.4s the clip would be past its natural end — in that case skip sound creation entirely (don't start a new alarm for an old fire the player can see winding down).
- **Multiple Clockmaker Notebook dialogs** → Not possible; VS allows only one open dialog per type. No multi-instance risk.
- **GlobalVolume = 0 (player mutes game)** → VS multiplies our value by `GlobalVolume` in OpenAL; at zero the sound is silent naturally. No special handling needed.

## Migration Plan

Additive-only change. No existing save data is affected. Ship in next patch release. No rollback complexity: removing the OGG file and `ScribeAlarmSound` class reverts the behavior.
